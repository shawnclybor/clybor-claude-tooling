What happened & why it mattered

The trigger

A recurring failure — tool Desktop_Commander__list_directory not found — kept interrupting work. It was escalated through the root-cause protocol rather than retried blindly.

Root cause: Cowork now reaches local tools through a single remote-devices bridge, which re-namespaces every local tool (mcp__remote-devices__…). The governance system was written against the old bare names, so it kept constructing tool names that no longer exist.

Why it mattered beyond one error

The loud error was harmless. The real risk was silent: a governance enforcement gate (it verifies the right governance skill is loaded before a governed tool runs) matches tools by name prefix.

As Cowork's naming surface migrates — legacy UUID → friendly name → bridged — that gate would quietly stop matching and let governed tools slip past unchecked. The fix closes that gap before it opens.
