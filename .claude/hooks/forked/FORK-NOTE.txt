guard-pack-redos-fix — a fork of vendor/guard-pack, taken 2026-09-21.

Why it exists
  vendor/guard-pack/lib/protect-secrets.js has a catastrophic-backtracking bug in the
  grep-env pattern. The three alternatives in

      (?:"[^"]*"|'[^']*'|[^|;&])*

  overlap: the catch-all branch also matches the quote characters the first two match,
  so a command naming grep/rg/egrep/fgrep/ag/awk/gawk, carrying many quotes, and lacking
  a trailing .env explores exponentially many partitions before failing.

  Driver is quote count, not length. Measured 2026-09-21 on real commands from this
  machine: 22 quotes 3.2ms, 34 quotes 50ms, 38 quotes 590ms, 46 quotes 6291ms — the last
  on a 663-char command. A synthetic 241-char command with 52 quotes never returned in 8s.
  1,150 of 28,083 Bash calls in a 30-day window (4.10%) sit above that threshold.

  With timeout: 5 on the guard entry, each of those was a silent skip of ALL SEVEN guards,
  not just protect-secrets — Claude Code treats a timed-out hook as failed and allows.
  Verified directly: a hook returning "deny" after 10s against a 5s budget did not block.

The change
  One character class, in lib/protect-secrets.js, grep-env only:
      [^|;&]   ->   [^|;&"']
  Everything else in this directory is byte-identical to vendor/guard-pack.

  Measured after: whole 28,083-command corpus in 29ms total, 0.22ms worst single command.
  No behavioural divergence on five true positives (grep SECRET .env, grep -r 'api'
  .env.local, awk "{print}" .env, rg TOKEN ./config/.env, egrep foo .env) or four controls.

Why a fork and not an edit in place
  vendor/README.md: files there are byte-pinned against their upstream test suites, and a
  local edit silently diverges from the tests that make them trustworthy. That README's own
  escape hatch is to fork out of vendor/ under a new name. This is that.

On re-vendor
  Diff the new upstream protect-secrets.js against this file. If upstream has taken the
  fix, delete this fork and repoint settings.json back at vendor/guard-pack. If not,
  re-apply the one character class and keep the fork.

Second change, 2026-11-04 — git-safety judges every repo the command could touch
  Upstream git-safety asked `git branch --show-current` in the hook's own directory, so
  `cd /other/repo && git <commit>` was judged by the session's repo. Measured that day: a
  commit onto main in one repo was allowed (session on a side branch elsewhere), and a
  commit on a side branch was denied (session on main).

  Design (after three chaos rounds): over-approximate, and read every command twice.
  - Quote-aware reading finds repos and subcommands (paths with spaces, -C "$(...)");
    a quote-blind reading finds verbs hidden in any string; the results are unioned, and
    quoted strings are re-read as commands. Quoted heredoc bodies (<<'EOF') are data.
  - Candidates = the session directory plus every cd / pushd / git -C / env -C target
    (variables with several possible values contribute all of them). The session
    directory is dropped only when the command starts with `cd <path> &&` (outside any
    subshell) or every verb call names its repo with -C.
  - Deny if any candidate is on main/master, if the command switches to main first, if a
    target cannot be resolved or does not exist yet, or past 50 candidates. From any
    branch, moving/deleting/renaming/pushing to main/master is denied.
  - `git pull` stays allowed (switch to main + pull after a PR merge is the normal route).
  - Accepted costs: with a main-branch repo in play, text that merely names a verb (an
    echo, an unquoted heredoc) is blocked, as upstream did; clone-then-commit in one
    command is denied. Out of scope: disguised commands (verb built in pieces, interpreter
    strings such as awk system()), config-defined git aliases, ssh, scripts in files.
  Files: lib/git-safety.js, guard-pack.js (passes the session cwd), test/ (36 tests,
  including the probes from all three chaos rounds). Validated on 10,300 historical
  commands: 0 exceptions, worst 10 ms; pathological inputs worst under 20 ms.
  This fork now differs from vendor/guard-pack in lib/protect-secrets.js, lib/git-safety.js,
  guard-pack.js, and the added test/ folder.
